AIエージェントに作業を頼むと、待ち時間が発生します。エージェントが考えたりコードを書いたりしている間、人間はただ待つだけです。この待ち時間が、私はもったいなくてたまりませんでした。

Claude Codeには、この待ち時間を消すための「並行開発」の機能が数多く用意されています。本記事では、私が実際に使っている並行開発の機能を、利用シーンとあわせて紹介します。

## 並行開発とは

私は「並行開発」を、次の3つの軸で捉えています。

- 複数の作業を並行してやる
  - 同じリポジトリで複数の作業を進める（worktree）
  - フロントエンドとバックエンドを同時に進める（teammate）
- 生活と仕事を並行してやる
  - タスクを投げて手を離し、寝ている間や移動中も開発を進める（background・remote control）
- ローカルとリモートを並行してやる
  - ローカルで始めた作業をクラウドに逃がしたり、クラウドの作業をローカルに呼び戻したりする（クラウドセッション・teleport）

「1つ頼んで待つ」のをやめて、複数の作業を同時に走らせる。その切り口がこの3つです。それぞれの軸を支える機能を見ていきましょう。

## worktreeで1つのリポジトリ内を並行開発する

worktreeとは、Gitの機能です。1つのリポジトリに対して複数の作業ディレクトリを作れます。`.git`の実体は共有されるため、リポジトリを丸ごとクローンし直すよりディスク消費が少なく、高速に作業ディレクトリを増やせます。

Claude Codeはworktreeをネイティブにサポートしており、エージェントごとに独立したworktreeを割り当てて作業させられます。エージェントごとにファイルシステムが物理的に分離されるため、**複数のエージェントが同じリポジトリで同時に作業しても、ファイルの編集が競合しません**。

https://code.claude.com/docs/en/worktrees

### 利用シーン・実例

「検索機能」と「お気に入り機能」のように、互いに別ファイルで完結する機能を同時に作らせるのに向いています。コツは、**別ファイル・別ディレクトリに閉じる単位でタスクを割り当てる**ことです。グローバルCSSや共通の型定義のような、共有ファイルを同時に触らせると競合するのです。

大規模な変更には`/batch`コマンドが便利です。変更内容を5〜30個の独立したユニットに分解し、各ユニットを別々のworktreeで並行実行して、それぞれがPRを作るところまで自動で進みます。

また、`.worktreeinclude`ファイルを使うと、`.env`のようなgitignore対象のファイルを各worktreeに自動コピーできます。環境変数がなくて動かない、という並行開発で起きがちなトラブルを潰せるので、地味にうれしいポイントです。

## teammateでフロントエンドとバックエンドを同時開発する

teammate（Agent Teams）とは、1つのリードエージェントが複数のチームメイトエージェントを編成し、チームで並行作業させる機能です。各チームメイトは独立したコンテキストを持ち、共有タスクリストをもとに自律的に作業を分担します。

執筆時点では実験的機能であり、環境変数`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`で有効化します。

https://code.claude.com/docs/ja/agent-teams

### 利用シーン・実例

実務では、フロントエンドとバックエンドが別リポジトリに分かれていることが多いでしょう。teammateを使えば、フロントエンド担当とバックエンド担当のエージェントを同時に走らせ、「登録フォーム（フロントエンド）」と「登録API（バックエンド）」を1人で前進させられます。最終的に、**それぞれのリポジトリで別々にPRが立ちます**。1人で2つのリポジトリが同時に進んでいく感覚は、なかなかの気持ちよさです。

## backgroundで「生活」と「開発」を並行する

`/background`コマンド（短縮形は`/bg`）を使うと、現在のセッションをバックグラウンドエージェントとして切り離し、ターミナルを解放できます。切り離したあともタスクは進み続け、`/tasks`コマンドでバックグラウンドの作業を一覧できます。

https://code.claude.com/docs/en/agent-view

### 利用シーン・実例

「ダークモード対応しておいて」のような軽めのタスクを投げて`/bg`で切り離せば、その後は人間が張り付いている必要はありません。私はタスクを投げてから食事をしたり、子どもと遊んだりしています。**開発が進む時間と生活の時間が、同時に流れる**ようになります。

## remote controlで外出先から指示を出す

remote controlは、ローカルPCで動いているClaude Codeのセッションを、スマートフォンのClaudeアプリなどの別デバイスから確認・操作できる機能です。セッション内で`/remote-control`コマンドを実行して使います。

セッションはあくまでローカルPC上で動き続けるため、ローカルに育てた設定やスキルをそのまま使えるのが強みです。詳細は次の記事で紹介しています。

https://zenn.dev/ubie_dev/articles/claude-code-remote-control-intro

### 利用シーン・実例

backgroundと組み合わせると真価を発揮します。タスクを投げてPCを閉じ、移動中にスマートフォンから進捗を確認して、必要なときだけ追加指示を出す。PCの前にいなくても開発が進み続けます。

## クラウドセッションとteleportで、ローカルとリモートを行き来する

Claude Codeの作業は、クラウド（[claude.ai/code](https://claude.ai/code)）でも実行できます。ターミナルから`claude --cloud "タスク内容"`と起動すると、作業がクラウド環境で実行されます。ローカルPCのリソースを消費しないため、PCを閉じてもタスクは進み続けます。

逆方向、つまりクラウドのセッションをローカルのターミナルに呼び戻すのが`/teleport`コマンド（短縮形は`/tp`）です。クラウドセッションのブランチを自動でフェッチ・チェックアウトし、会話履歴ごとターミナルに引き継げます。

https://code.claude.com/docs/ja/claude-code-on-the-web

### 利用シーン・実例

「重めのリファクタリングをクラウドに投げて外出し、帰宅後に`/teleport`でローカルに呼び戻して仕上げる」という往復が定番の使い方です。

なお、`/teleport`の利用にはclaude.aiのサブスクリプション認証が必要です。また、テレポート前にローカル側が「クリーンなGit状態・同一リポジトリ・ブランチがプッシュ済み」であることが求められます。

## auto-fixでPRのCIを自動修正する

`/autofix-pr`コマンドを実行すると、現在のブランチのPRを監視するクラウドセッションが起動します。CIが失敗したり、レビューコメントが付いたりすると、自動で修正してプッシュしてくれます。

利用には、Claude GitHub Appをリポジトリにインストールしておく必要があります。

https://code.claude.com/docs/ja/claude-code-on-the-web

### 利用シーン・実例

PRを出したあとの「CIコケてないかな」という定期巡回から解放されます。私はPRを出したら`/autofix-pr`を仕掛けて、すぐ次のタスクへ移っています。人間がCIの結果を待つのではなく、**CIの面倒はエージェントに見させて、人間は次の作業へ進む**のです。

## goalで長時間タスクを自走させる

`/goal`コマンドでゴール（完了条件）を設定すると、Claude Codeは条件を満たすまでターンをまたいで作業し続けます。

https://code.claude.com/docs/en/commands

### 利用シーン・実例

「全機能のE2Eテストを追加して、テストがすべて通るまで」のような長時間タスクと相性抜群です。人間の仕事は、**Doneの定義を明確にすることと、上がってきた成果をレビューすること**に変わります。曖昧なゴールを渡すと迷走するので、完了条件は具体的に書くのがコツです。

## /btwで、作業を止めずに脇で質問する

複数の作業を並行させていると、「そういえばあれってどうなってたっけ？」という細かい疑問が湧いてきます。そんなときに便利なのが`/btw`コマンドです。

`/btw 質問内容`と入力すると、**Claudeがタスクを処理している最中でも**、メインの作業を中断せずに質問へ答えてくれます。質問と回答は会話履歴に残らないため、メインのコンテキストを汚しません。

https://code.claude.com/docs/en/interactive-mode#side-questions-with-%2Fbtw

### 利用シーン・実例

長時間タスクを走らせながら「さっき修正したファイル名なんだっけ？」と聞いたり、レビュー待ちの間に「この設計にした理由をもう一度教えて」と聞いたりできます。サブエージェントは、全ツールを使える代わりにコンテキストが空の状態から始まります。`/btw`はその逆で、会話の中身を全部見えるまま、ツールだけ使えません。

## さいごに

かつての私は、1つのClaude Codeに作業を頼み、その完了をじっと待っていました。今は、worktreeで機能を並行させ、重いタスクはクラウドに逃がし、移動中はスマートフォンから指示を出しています。**人間の仕事は「コードを書いて待つこと」から「タスクの境界を設計し、レビューすること」に変わりつつある**と感じています。

まずは`/bg`で1つタスクを裏に回すところから、並行開発を始めてみてください。待ち時間が消える快感は、一度味わうと戻れません。
